# RNL-003: total event cost of exact reuse at larger toy sizes

Status: pre-execution protocol. RNL-002 established a correct reuse contract,
not a speed improvement. This single CPU study asks: **when does the complete
event using that contract take less time than the same uncached event?**
The sizes represent a synthetic size sweep, not an LLM workload or model quality.
No packed kernel, training, application integration or backend replacement.

## Fixed comparison

Use 3 immutable experts, top-1, square input/state dimensions D = 16, 64, 256,
1024. Both U (uncached) and M (one-entry memoized raw product) use identical
byte-index matrices and the shared, ordinary row-major decoding/multiply loop.
Codebook [-1,0,1], FP32 arithmetic and original operation order: input/gate
router terms then 0.15*state*gate, stable lowest-index tie, tanh(product +
0.25*state), decay 0.55*state + (1-0.55)*output. Zero inputs are skipped.
Original parser/source and earlier experiments stay unchanged. Dynamic sizes
require a small worker using the same recurrence; this is not original binary
performance. Preserve FE_TONEAREST, SSE rounding, FTZ and DAZ settings.
The original CLI rejects D>256; D1024 is generated instrumentation only.

Only M's reuse is enabled: expert index plus every input's FP32 bits; values
stored by value, invalid on reset, model immutable. Router, activation and state
update run on every event. Same event routine and non-inlined matrix kernel in
both modes. Timed loops have no per-multiply instrumentation or trace allocation.
No compiler/kernel tuning after results within this attempt.

Model PRNG: xorshift32 (unsigned shifts 13,17,5), seed 0x524e4c33 freshly reset
for each D. For experts in index order, generate D gates then D*D byte indices,
each draw modulo 3; gates are draw-1 and indices decode through the codebook.
Input PRNG seed 0x494e5033 freshly reset for every D/pattern. Corpus has 100
events in blocks of length L = 1, 2, 10 (nominal repeats 0%, 50%, 90%). For each
new block generate D components from (draw & 1) ? +0.25 : -0.25, then set input[0]
to 0.25 + block_index/1024. Duplicate the resulting vector within that block.
Different blocks have distinct first components, including the corpus wrap.
Record actual adjacent-input repeat rate and actual expert-and-input cache hit
rate, since repeated input need not retain its expert. Fixed seeds are controls,
not sampled populations. Dense nonzero dyadic inputs avoid sparse-work confounds.
Report repeated events/N and equal adjacent pairs/(N-1) separately: the first
event and every corpus wrap differ from the preceding block. U has zero hits;
check M hit counts across identical repetitions and evaluations=N-hits.

## Correctness and independent checks before interpreting timing

For each of 12 scenarios run the 100-event corpus independently from zero and
the tiled [0.25,-0.5,0.75] state (200 steps/scenario). Compare U/M router scores,
chosen expert, raw product, output, before/after state bit-for-bit. The sum of
integer input units times ternary weights, accumulated independently as int64,
is an exact raw-product oracle: divide by 1024, with absolute intermediate
integer sums bounded below 2^24. Here |input*1024| <=355, so D<=1024 bounds
every absolute partial sum by 363520, below 2^19. No zero-input mapping or random
floating rounding is needed. Use the oracle on every validation step/row. Retain
compact hashes/counts plus the first complete discrepancy, rather than megabytes
of duplicate traces. Retain D16 U traces for an independent Python FP32 oracle,
including generated model/input fingerprints and initial state.

Rerun the small existing RNL-002 independent checker against its preserved
results as a harness control; do not reinterpret it as a new execution. A
deliberately incomplete input-only key must still fail its expert-changing
repeat. Original signed-zero control remains applicable; no approximate key.
During timing compare paired event count, hit count, scalar output checksum and
final full-state hash. These supplement, rather than replace, validation.

## Timing protocol and decision rules

One timing worker per D/L scenario measures both U and M in the same process.
Use Windows QueryPerformanceCounter, record frequency and minimum positive
delta across 2000 consecutive reads. Reject missing/nonmonotonic/invalid clock.
Record MSVC version/flags, binary/source/protocol hashes and affinity controls.
Wall time measures contention from other work; do not inspect or pause it.

Calibrate using U only, before any comparison: start at 100 events, reset VM
outside each timed interval, scale by whole corpora toward 50ms. Stop calibration
at the first interval >=50ms or the cap. After a shorter interval set the next
count to ceil(N * 0.050 / seconds / 100) * 100, at least N+100 and clamped to
the cap rounded down to a multiple of 100. At most 4 calibration intervals, no more
than 100000 events or 200 million D*D terms per interval. Calibration is excluded
from comparison. Use the resulting single count for U and M. One same-count
warmup per mode, excluded. Five paired measurements, alternating order U/M then
M/U. Reset state/cache outside each measurement. No adaptive extra repetitions.

Time the entire event sequence: router, key lookup/bit comparison and copies,
matrix decode/multiply on misses, activation/state, scalar checksum. Exclude
model/corpus generation, VM construction/reset, validation, memory API calls,
serialization/file writes. Both modes perform the same checksum addition of
output[0] per event; final state hashing happens after the timer. Cache storage
and all mutable scratch are preallocated, as disclosed. Infer matrix work from
evaluation counts and dense D*D; do not time an instrumented inner loop.
Each interval brackets the entire N-event loop with two QPC calls, starting
from zero state and a fresh invalid cache; report interval/N, never per-event
QPC timings. Require zero actual hits for every L1 control.

Retain each raw tick interval, paired U/M ratio, min/median/max latency and
actual hit rates. A local benefit is supported only if all equality/control
checks pass, every batch is >=5ms and >=10000 empirical timer quanta, median
paired U/M >=1.10, all five ratios >1.05, and max(M time) < min(U time).
Otherwise record slower, no demonstrated benefit, or insufficient resolution
as appropriate. Five fixed pairs are descriptive evidence, not a statistical
population or deployment guarantee. An apparent >=10% M win in a zero-hit
control invalidates that dimension's benefit interpretation pending review.
No timing rerun/tuning to obtain a desired outcome.

## Memory and storage accounting

Do not derive memory savings from MACs or matrix payload size. Cache adds a
retained input key (4D bytes), raw product (4D bytes), expert/validity metadata
and vector/object/allocator overhead. Report actual vector capacities, sizeof
objects, gates, matrices, corpus and shared scratch without double counting.
Report an incomplete allocation subtotal with unknown allocator/CRT overhead.

Separate memory workers for each D/mode, using L10 and one 100-event warmup,
avoid correctness/trace allocations and mixed U/M high-water. Record live
working set and private bytes after setup/warmup, OS peak working set and
private/commit where available, plus supervisor peak values. Three --empty
same-binary startup controls give context, not an exact subtraction. Whole
process metrics are noisy and include CRT/OS/allocator effects. No reliable
cache memory saving is expected or presumed. No model disk file is created;
report generated representation bytes, executable size and result artifact
bytes separately. Disk-loading time and model quality remain unmeasured.

## Caps, review, publication and stopping

Reuse run_bounded.py unchanged: one logical CPU affinity, 256MiB working set
and committed memory, owned worker only, no child workloads. At most 600 seconds
aggregate wall time for validation/calibration/warmup/timing/memory workers,
less than 10MiB retained outputs, each direct result preflight below 1MiB,
each guard stream plus metadata below 64KiB. Parent checks remaining time and
output budget before launches. A worker may receive at most the remaining time.
The resource guard is not a filesystem/network security sandbox.

Pre-execution protocol commit and independent design/source review precede
workers. Freeze implementation/checker hashes before launch; preserve all failed
or partial records and corrected hashes if a defect stops execution. Stop on
provenance/resource/FP/nonfinite/equality failure, invalid oracle, unreviewed
side effects or a cap. Do not add sizes, rerun for better timing or optimize
beyond this study. If measurements are inconclusive, report them and stop.

Research artifacts only on research/rnl-sandbox. After independent result and
claims review, only docs/atlas/research.html may change on main, preserving all
concurrent application and other Atlas changes. No Candidate/Integrated stage
promotion merely because synthetic repeat traffic is faster. A later real
Revia trace study would require a separate decision and consent-aware inputs.
