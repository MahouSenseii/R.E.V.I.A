# RNL-002: exact matrix-product cache contract

Status: pre-execution protocol. One CPU-only question, chosen from FIRST-001's
observed cache failure: **can a one-entry cache reuse only the pure expert
matrix-vector product while preserving every recurrent update bit-for-bit?**

The alternative size sweep is deferred. Establishing which computation is safe
to cache addresses the demonstrated semantic defect directly. This experiment
does not test whether caching improves latency or Revia's language abilities.

## Fixed contract and single comparison

Use FIRST-001's exact immutable sample model (SHA-256
`624a406e865feb8c3274537e2d0667b56992744f2277aa42d1da1f25469e12dd`),
original source hash, MSVC flags and FP32 operation order. Three experts, 3x3
matrices, top-1, the same gates/codebook/decay. No training or model changes.
Verify round-to-nearest and record SSE rounding/FTZ/DAZ settings in every worker;
reject changed FP control settings. This contract covers numeric trajectories,
not floating-point exception flags, elapsed time or other observable side effects.

The model is immutable for one worker/cache lifetime. Router scores and expert
selection run on every input. A cache miss computes the selected matrix product
in the original accumulation order, before activation and state update. A hit
reuses those exact FP32 sums; it still runs activation and updates state.

| Mode | Matrix-product reuse | Purpose |
| --- | --- | --- |
| U | None | Uncached recurrence reference |
| M | One-entry key: selected expert index plus exact input FP32 bits | Proposed contract |
| B | Same cache, deliberately omit expert index from the key | Negative control; must be rejected |

Only key completeness varies between M and B. No approximate comparison or
cross-model reuse is allowed. A reload/change would require cache invalidation
or a model version in the key; neither is exercised here. Conservative misses
for different signed-zero encodings are intentional. Memory is bounded to one
input vector, one raw product vector, an expert index and validity flag.
Reset the entry for every case/state seed and store product values by value;
activation must never overwrite the cached raw sums.

## Frozen inputs and acceptance

Reuse all eight FIRST-001 cases with their exact ordering and threshold-adjacent
bits. Add two cases, fixed before execution:

- `RouteRepeat`: 16 copies of `[0,1,1]`. From zero state the first selected expert
  must be coding (index 1) and the second vision (index 2). This challenges a
  cache keyed only by input, even though the input repeats.
- `SignedZero`: `[1,+0,0]` twice, `[1,-0,0]` twice, then `[1,+0,0]` twice.
  Require miss/hit/miss/hit/miss/hit decisions while the selected expert remains
  conversation. Reconstruct inputs from uint32 bits, since JSON numeric `-0`
  alone can lose its sign when parsed.

Run all ten cases independently from zero and `[0.25,-0.5,0.75]`: 20 trajectories,
280 steps per mode. Freeze inputs, model/source/worker/checker hashes and this
protocol before the first worker launch. Do not search for a friendlier corpus
after results. Retain full input/state/router/product/output bits and counters.

The independent FP32 oracle from FIRST-001 validates U at its declared `1e-6`
tolerance, retaining cross-libm rounding limits. M must match U's selected
experts, router scores, raw matrix products, outputs and before/after states
bit-for-bit on every step. M must actually hit on an exact repeated key and miss
on the expert-changing repeat. B must diverge on the predeclared route transition;
failure to expose B means the test is inconclusive, not a pass.

Count matrix MACs, router products, activations, state updates, key comparisons,
hits/misses and retained cache capacities separately. Saved MACs are operation
counts, not speedup evidence. Do not time M against U in this experiment; do not
interpret the correctness contract as lower total memory or faster inference.

## Execution and stop rules

Reuse the reviewed Windows resource supervisor and existing stdlib unittest
oracle; add a small separate worker/checker, leaving FIRST-001 source/results and
the uploaded originals unchanged. Review new code independently before execution.
No dependencies, servers, GPU, training, network access or other workloads.

At most one logical CPU, 256 MiB worker working set and committed memory, less
than 600 seconds for the full attempt and less than 10 MiB retained results.
Each worker preflights combined direct output below 1 MiB; the parent accounts
for guard logs/metadata and all direct outputs before each launch. These resource
controls are not a security sandbox or proof of one OS thread.

Stop on missing provenance, a resource/control failure, nonfinite values,
unexpected side effects, M divergence, or an ineffective B negative control.
Preserve failed/partial records. No implementation tuning after measured failure
within this attempt; any correction must retain its failed result and new hash.

Independent review precedes publication. Artifacts stay on `research/rnl-sandbox`;
only `docs/atlas/research.html` may update on main. Even a passing contract stays
Measured/toy, with no Candidate or Integrated promotion. A later size/throughput
sweep would be a separate decision and experiment.
