# M2/M3 local acceptance

The Continuous Improvement Studio v3 campaign implemented and verified M2 and M3
on October 3, 2026, preserving the accepted M1 foundation. Acceptance applies to
the local working-tree candidate and the controlled contracts below. The Director
assembled the work; real Supervisors, Workers and independent reviewers supplied
bounded packages and separate reviews. No source was staged, committed or pushed.

## M2: independent companions and current authority

Companion IDs identify separate earned minds; authored profiles remain blueprints.
The registry and Qt selector use captured absolute paths without changing process
working directory. Existing memory, router tiers, identity, preferences, goals,
archives, voice data, logs and evaluations receive their owner's private paths.
Model weights and executable tools remain shared installation resources. Neutral
profile seeds cannot borrow the original companion's authored private profile.

Retirement invalidates the session generation before workers are joined. Captured
origins gate queued memory work, runtime events, background completions, goal
dispatch and UI callbacks. A → B → A keeps private recall and denies old A work;
switching also clears outgoing chat, voice and Studio drafts. A process-local lease
arbitrates one foreground model/device owner.

Explicit migration inventories known private roots, copies SQLite through its
backup API, retains stable IDs and committed WAL data, stages hashes and a
versioned manifest, and revalidates before publication. Interrupted or invalid
bundles stay inactive and the source survives. The final thirteen-function suite
also covers strict whole-document JSON/JSONL parsing, raw NUL/trailing garbage,
junction refusal, and a synthetic `no_space_on_device` after actual staged-copy
progress, followed by validated reuse and successful retry.

Live authority composes the machine ceiling, companion defaults, trusted scoped
grants, denials, expiry, task ancestry and emergency stop. Goal runs receive fresh
runtime task identities independently of persisted goal IDs; failed registration
admits no action. The host retains the shared ledger across selection. Final
effect checks consume current authority and cancellation, including admission
after the native UIA commit callback. A disposable owned Windows button verifies
that callback revocation/cancellation blocks Invoke while an authorized control
still succeeds.

## M3: a bounded analytical Agent Studio

The implemented graph contains a parent companion, two independent workers and a
reviewer. Workers overlap; dependencies pin verified artifact IDs, versions and
hashes. Execution success, evidence verification, charged parent review and parent
acceptance remain separate. Accepted output is projected through the existing
runtime and response filter.

The owner retains attempt history, cancellation, cumulative request/attempt/time
and reported-token budgets, private checkpoints and explicit restart/resume. The
diagnostic provider deliberately pauses on incomplete evidence. Changed input or
evidence justifies recovery; an identical retry is refused. The connected runtime
and UI exercise recovery, reviewer completion, parent review and separate final
acceptance in five total requests. Saved provider mode must match its workflow ID.

The glass Qt panel exposes actual hierarchy, states, attempts, safe failure
reasons, dependencies, verified references, provider intervals and current
observation age. Missing observations show a stale snapshot rather than invented
activity. Provider-reported model/token values remain optional; unavailable usage
and internal model queue timing are labeled honestly. Node interval accounting
does not sum parallel children into parent elapsed time.

## Remaining limits and delivery order

Migration requires quiesced writers; configured external legacy data needs
explicit handling. No real user data was migrated. The injected disk-full test
does not measure physical disk saturation or short writes.

Authority is a live process ledger. Durable grant restoration and a production
authenticated owner UI remain future work; the trusted verifier boundary fails
closed without valid proof. One real foreground model/device host is supported;
concurrent isolated fixtures establish storage and origin separation.

M3 providers are bounded, read-only analytical collaborators with cooperative
cancellation. The local model adapter is connected, but this campaign did not run
a live model performance experiment. Analytical evidence-contract validation does
not claim external tests or OS actions ran. No autonomous OS agent, self-modifying
deployment, physical hearing, microphone/camera quality, arbitrary real desktop
automation or cross-platform runtime acceptance is inferred.

M4 remains reviewed neutral skills and evidence learning. M5 remains evaluated
social/voice continuity and consent-based recognition. M6 remains protected,
isolated self-development with exact-artifact review and authorized deployment.
