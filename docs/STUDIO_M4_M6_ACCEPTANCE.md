SpeakerEnrollmentDialogue owns the bounded consent/sample/confirmation flow:

1. A private typed `remember my voice` request identifies the current local person.
2. `I consent to local speaker recognition only` arms the next transient sample.
3. The existing resolver extracts bounded features before its WAV is released.
4. `confirm this voice sample` permits the separate durable transaction.

The dialogue expires after two minutes and permits two sample attempts. Unknown
voice requests receive instructions; voice cancellation can always withdraw the
pending sample. Stop, profile, audience and companion changes cancel the purpose.
It does not start recording or retain raw audio. Confirmed re-enrollment replaces
one bounded local template without learning from the recognizer's own guess.
Recognition consent does not authorize voice cloning.

Both this flow and selected-WAV UI enrollment use
`RelationshipRegistry::SaveConsentedSpeakerSample`. Consent and template publish
together only after the existing atomic identity save succeeds. Failed extraction,
stale admission or failed persistence preserves the working template and consent.
Six connected native fixtures passed, including durable reload, transient resolver
attribution, cancellation, stale private-input refusal and failed-WAV/save
preservation. The synthetic PCM tones are not real-person recognition benchmarks.
