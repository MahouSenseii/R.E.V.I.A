01 / LATEST LOCAL STUDIES

What the newer studies found.

Positive, negative and stopping results are shown together. Detailed methods, frozen artifacts, checkpoints and traces for STATE-011–017 remain local and unpublished.

STATE-018Baseline · no training

A small model with a memory store beat a large one that held everything in context.

Qwen3.5-0.8B filing notes into a store answered 88.6% of questions in 685 MiB of VRAM; the 9B with the whole history in its context answered 44.7% in 5,480 MiB. With the store, the 4B and 9B reached 94.7% and 94.5%.

Detail & evidence scope

STATE-018, 12 November 2026, the first step toward the owner’s goal for RNL: a model structure that is smarter, remembers better and needs less VRAM. It measures the two plain ways a local model can remember, so a new structure has a number to beat. Same people-and-facts task as STATE-017 with updates, corrections, misspelled names and aliases; 80 development histories, 640 questions; the sealed test stayed closed and nothing was trained. In context: 0.8B 69.5%, 4B 59.8%, 9B 44.7%. Filing each note into the unlimited keyed store, one model call per note: 88.6%, 94.7%, 94.5%. A rule-based extractor with the same store scored 640/640. In context the 0.8B answered with an old value 112 times; the 4B and 9B almost never did, and instead declined 242 and 346 times, mostly when the name was misspelled or an alias. On exactly spelled names context still gave 75%, 85% and 83% against 96%, 99% and 100% with the store. From 8 to 64 facts every model lost 11–22 points in context and at most 2 with the store. The store’s remaining errors were the model’s filing: aliases 55–82% correct, and 37–120 notes per run filed unusably. The same model needed almost the same VRAM either way; the saving comes from being able to use a smaller model. Filing cost 23–57 minutes for the 80 histories against 1–5 minutes to answer from context.

Local study · development data only · one prompt per arm, one run · synthetic task · the context prompt may make larger models decline misspelled names

Next This is the baseline, not a new structure: an explicit store beside an unchanged model. A learned part would have to help where the store’s gaps are, aliases and filing on small models, at the small model’s VRAM. No such training has been run.

HYBRID-CHECKStopping estimate

A learned name matcher had little room over a good store.

With a fairly tuned fuzzy store, a perfect name matcher would add only about 2.5 points on harder misspellings, and no memory or speed saving was available.

Detail & evidence scope

Pre-check before any training: a learned name-matching part in front of an explicit replace-on-write store. On 400 new development histories with three-letter typos, truncations, dropped vowels, sound-alikes and swapped halves (tuned on half, scored on the other half), the strong fuzzy store scored 97.5% with unlimited memory and 76.0% / 91.2% / 97.5% at 128 / 256 / 512 floats. A perfect matcher using the same stored names would score 100% / 78.7% / 93.6% / 100%, so the most any matcher could add was +2.3 to +2.8 points (paired 95% intervals within +1.6 to +3.6). A first baseline skipped character similarity under a budget although it already stored the names, which wrongly suggested 17–21 points of room; the corrected baseline is the one reported. Most remaining errors are typos equally close to another real name, or an artificial swapped-halves pattern a simple rule would fix. Stored names cost about 2 floats each, so a learned key cannot save memory here.

Local estimate · development data only · no training · not proof that every hybrid is useless

Next Stopped for this design. Other stores, noise types or tasks could leave more room.

STATE-017Negative result

Two trained RNL designs fell short of a simple store.

On development data, RNL stayed 7–32 points below a compact keyed store at every memory size tested; a diagnosed layout fix closed only part of the gap.

Detail & evidence scope

STATE-017: a synthetic memory task with people’s facts, updates, corrections, misspellings, aliases and overload, every system reading the same text through one extractor. Budgets of 64 / 128 / 256 / 512 floats per conversation, three seeds each, CPU only. Run 1 (36 models) was 17–32 points below the matched store; ideal storage with its own learned addresses reached only 44–73%, so its layout, not its training, was the limit, and most errors were another person’s value. Run 2 (27 models, rules frozen in advance) gave each attribute its own name-addressed block: +7–11 points over run 1 and +10–14 over a random-address control, but still 7–24 points below the store on every seed, with every paired interval below zero. Twice the training added under 1 point. Remaining failures: aliases (about 50% against 84% for exact names), many facts, and older facts fading under later writes. The confirmatory sealed test was never opened.

Local study · development data only · detailed source, checkpoints and traces unpublished

Next Closed under its stop rule. It does not show that RNL cannot work; other layouts, alias mechanisms, tasks and budgets are untested.

STATE-016Positive synthetic result

Separate addresses recovered the retained errors.

Fixed separate slots answered all 1,008 questions correctly, while the original and sham controls each answered 970.

Detail & evidence scope

STATE-016: 1,008/1,008 versus 970/1,008; 38 rescues and no new errors. Three frozen seeds, four supplied keys, eight values. No training updates. This isolates a useful memory-address intervention on this task; it does not establish general routing, language understanding or equal-capacity training.

Local study · detailed source and traces unpublished

02 / EARLIER WORK

What the public source supports.

The pinned public research branch contains methods and results through STATE-010. Atlas summaries of later studies do not make their full evidence public.

Existing prompt-prefix reuse was observed.

Cache-on reused 399 of 438 prompt tokens and both modes gave the expected 26-token answer.

Detail & evidence scope

One fixed-order Qwen3.5-0.8B pair: 4.666s versus 51.408s to first content, with each primer costing about 50.5s. This verifies an existing llama.cpp mechanism; it is not a reliable speedup estimate, a usual 4B result or a new RNL cache.

Exact reuse helped the synthetic repeat workload.

Repeated-event cases met the declared timing rule; zero-repeat controls had no benefit.

Detail & evidence scope

RNL-003: eight repeated-event conditions across four matrix sizes, median paired uncached/cached ratios 1.213–3.994. Retained buffers increased; no RAM reduction or real Revia savings were established.

The earlier neural readers missed reliability targets.

Some individual recall improved, but STATE-006–010 did not demonstrate reliable keyed memory.

Detail & evidence scope

STATE-010 scored 27.88%, 29.56% and 27.93% for three reader forms, versus 12.5% references. Every trial had 0/168 complete four-case groups. Earlier training and query-blind controls remain in the full records.

The cache must preserve the full computation contract.

Keying by selected expert and every input bit preserved 280 tested steps. A shortcut did not.

Detail & evidence scope

RNL-002 retained routing, activation and recurrent updates every time. The first supplied toy cache changed behavior, so skipped work could not count as an equivalent speed improvement.

Studies 011–018 and the comparison

Source deltas, per-example predictions, traces, frozen snapshots, the 63 STATE-017 checkpoints and the full comparison seal are held locally. This website does not supply them.

What a reproducible, reviewed handoff needs
  • Exact method/config/source/test deltas and all positive and negative results.
  • Fixture generators, seeds, evaluation definitions and per-example predictions/traces.
  • Three frozen delta snapshots, tensor inventory, original hashes and lineage.
  • The comparison fixture/parser, 32 retained requests/responses and completed 46-output seal.
  • An inventory mapping symbolic artifact IDs to sanitized filenames and export hashes.

Raw local logs/manifests can contain private paths and process metadata. The exact export inventory and destination need review before any upload. A summary alone does not reproduce these studies.

Improve incrementally; keep the evidence bounded.
