First experiment

FIRST-001: check the numbers and preserve the state. Compare the same tiny network using packed codebook indices, unpacked indices and ordinary numerical weights. Check every output and state update before comparing total memory and elapsed time.

Repeated and nearly repeated inputs must expose whether caching changes the answer. A smaller weight payload alone does not count as a useful improvement. This toy check cannot establish language-model quality or predict savings for Qwen.

Method, limits and stop criteria

Use identical handcrafted parameters, deterministic expert tie-breaking and state updates. Include all experts, router weights, codebook, headers, buffers and state in the accounting. Check cold starts, alternating inputs, nonzero initial state, repeated inputs and perturbations around the novelty threshold. Compare full output and state trajectories against an uncached reference; the authored cache is expected to fail this equivalence check.

Record file bytes, resident representation bytes, peak process memory and warmed end-to-end latency separately. Count executed matrix operations and router/state work separately. Any timing comparison needs repeated independent samples and its uncertainty. Do not infer a speedup from operation counts.

Pass the correctness gate only if the exact computation agrees within a predeclared absolute tolerance of 1e-6, counters match the executed loops and accounting reconciles. A state mismatch disqualifies the affected caching claim. A valid negative result is useful. Stop on missing provenance, invalid counters, unbounded approximation error or a resource-limit breach; no savings claim follows.

Planning budget, not a measurement: one CPU thread, 256 MiB process-memory cap, ten minutes maximum execution and under 10 MiB of results. No GPU, training, dependency installation, model downloads or access to another running test. Local attachment transfer is blocked by a Windows metadata-helper limitation, so no uploaded program has run.

Next gate after the toy check: design one comparison against a pinned Qwen model and llama.cpp build. Model hash, settings, held-out cases and resource budget must be recorded first. That comparison is not scheduled or run.

What we know

The supplied HTML describes a three-input, three-state, three-expert illustration with handcrafted weights. The C++ findings below come from the earlier source review and have not been independently rechecked in this workstream.

Static findings and their evidence limits
  • The HTML matrix loop performs nine multiply-add iterations for a new event while its one-hot-input counter displays three. Routing, activation and state-update overhead are outside that counter.
  • The earlier C++ review found that nine packed matrix bytes become 27 one-byte indices when loaded, with all experts resident. Neither number is total runtime memory.
  • The authored novelty cache skips state updates on repeated inputs even though routing and output depend on state. Its approximate threshold supplies no error bound.
  • The earlier C++ review found that inspection uses E*(N+3)/4 instead of per-expert packing E*((N+3)/4), with integer division.
  • The illustration honestly labels 113 full-file bytes versus 108 matrix-only FP32 bytes. These compare different scopes and do not prove total savings.
  • No tokenizer, learned weights, training loop, text inference or GGUF support is demonstrated. Existing toy checks do not establish a numerical state trajectory, language quality or VRAM use.

These are static observations, not new execution results. Local ZIP materialization is incomplete; no local source digest or independent C++ audit is claimed.

Related research and existing Revia evaluation paths

AQLM studies learned additive quantization. Switch Transformers studies sparse expert routing. They motivate questions; their results do not validate this prototype. QLoRA is a separate adapter-training approach, not an RNL result.

Reuse Revia's answer-quality gate, golden cases and offline-learning lineage and review rules when applicable. Their existing evidence retains its original scope.

Path into Revia

Keep useful ideas eligible for later integration. First reproduce the benefit against an unchanged baseline and record tradeoffs. Then review the held-out quality, safety and privacy results and propose a small change. Integration needs explicit authorization and a tested rollback; passing an experiment never merges or replaces a model automatically.

Memory, corrections and future evaluated adapters remain a separate practical learning path. Any future training needs consent-aware data lineage and withdrawal checks. Deleting an example later does not erase its influence from trained weights.
