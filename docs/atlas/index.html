IN REVIEW / 2026-11-12

Done and measured, not merged yet.

Six changes are on PR #50. They are not in the retained main revision or the installed app, and their measurements are small live samples.

In reviewPR #50

Text that has to be copied exactly is copied exactly.

File paths, phone numbers and search results came back altered because the repetition sampler penalised copying. It is now relaxed for turns that carry exact text and off for structured replies.

Detail & evidence scope

Found by replaying recorded requests against the Qwen3.5-9B with different sampler settings. A named path was copied correctly in 0 of 28 replies before and 9 of 10 after; a number from a search result 0 of 28 and 10 of 10; a stored phone number 0 of 18 and 18 of 18; recall across turns 0 of 8 and 8 of 8. Jokes and ordinary chat keep the stronger setting. Small samples, one model.

Next Watch for repeated phrasing in long chats now that the brake is lighter on some turns.

In reviewPR #50

A file you name is read before she answers.

She described files she had not opened. Full paths inside approved folders are now read by the host before the model’s first step.

Detail & evidence scope

A wording change to the tool description was tried first and changed nothing. With the host reading first, 4 of 4 live file questions were answered from the real content. Bare file names resolve against recently named folders, then a single approved folder.

Next Check file names that match in more than one approved folder.

In reviewPR #50

Agents start when asked, look before answering, and finish while you talk.

“Use your agents” always starts the task, a worker’s first step must open something, write-ups validate, and workers wait for a pause in the conversation instead of failing.

Detail & evidence scope

Replays on the 9B: a worker’s first step chose to do nothing in 20 of 20 before and read the file in 20 of 20 after; every write-up failed its schema in 10 of 10 before and passed in 10 of 10 after; the hand-off started in 8 of 13 before and 10 of 10 after. Live: 4 of 4 runs verified on an idle PC. On a busy PC 2 of 6 failed because a worker retried in the moment between messages and lost to the next one; with a one-second pause rule 3 of 3 were verified, and chat replies stayed near two seconds.

Next Repeat on more kinds of task; these were all one small bug hunt.

In reviewPR #50

A quick reply no longer costs the previous turn its memory.

A memory check still running when the next message arrived was thrown away. It now belongs to the conversation, not the single turn, and waits out the reply that interrupted it.

Detail & evidence scope

Seen with the Qwen3.5-27B, whose memory check takes three to five seconds: with messages three seconds apart it saved 0 of 2 facts before and 2 of 2 after, and recalled both after a restart. Two causes, fixed separately: retries ran against the same reply that had interrupted them, and the turn’s permission ended when the next message started. A dropped check is now logged. A check still waiting when the app closes is still lost.

Next Decide whether waiting checks should be finished or saved at shutdown.

In reviewPR #50

An agent run can fix a file, run its test and sign the work off.

With permission to write and to run an approved program, her agents now edit the file, run the test themselves and accept the result. Before, both trial runs stopped as unverified after a correct fix.

Detail & evidence scope

Agent Studio runs on the 9B, in a scratch copy of a small buggy project with one failing test. Five causes were found and fixed one at a time, each measured by replaying the recorded step 20 times the way the app sends it. A write’s receipt showed only a hash, so the worker could not tell what it had written. A worker allowed to write stopped after reading in 9 of 20; asked to carry the task out and told after its material that nothing was written yet, 0 of 20. In 8 of 19 writes the model copied the digest line from the read result into the file; the host now strips it. Asked to run the test, the checking worker stopped in 20 of 20; when the owner’s request names an approved program it may not stop before trying, and it ran the test in 18 of 20. Every run repeated the program as its own first argument, which the host now drops. The reviewer and the acceptance check called a run whose test had passed verified in 8 and 9 of 20; told that each write-up speaks only for its own worker, 20 of 20, and no more often than before on a run whose test never ran (7 of 20 against 10). On the final build, five live runs: the file was fixed and the agents’ own test run passed in 5 of 5, and 4 of 5 were accepted in 41–61 s. The fifth used up the run’s 20,000-token budget before the acceptance check and waited for the owner. Running Python also needs the interpreter permission, not only an approved executable.

Next Decide the token budget for runs that use tools; try a change that spans more than one file; the reviewer still accepts about a third of runs whose test never ran.

In reviewPR #50

She no longer re-reads guidance that has not changed.

Settings text, the guidance on how to speak from a feeling and her answer posture are the same from turn to turn. They now ride on the first message of the chat, which the model server already holds, and history lines she is about to read anyway are no longer repeated. Greetings and personal jabs are sent exactly as before.

Detail & evidence scope

Measured by replaying recorded turns straight at the model server on the 9B. Her first word took 0.52–0.56 s in a short chat and 0.84 s by turn 18, when each turn re-reads about 2,400 tokens of per-turn guidance at roughly 3,000 tokens a second. Each piece was moved alone and judged on about 120 replayed replies sent the way the app sends them: answers right, reply length, questions asked back, echoing the user. Feelings guidance, the answer posture and dropping repeated history lines each left replies unchanged; the rule against repeating the user’s wording made them worse and stays in the turn. With all kept changes, two live conversations re-read 1,045 and 1,115 tokens a turn against 1,648 and 1,587 before, prompt reading fell from 516 and 522 ms to 364 and 394 ms, and whole-reply medians from 1.83 and 1.72 s to 1.38 and 1.56 s (one run each). Replays of the last three pieces alone: first word 13–18% sooner, answers 86 of 87 against 84 of 86 and 53 of 56 against 54 of 56. Greetings re-read 750 tokens before and after. When a prompt must be compacted, everything returns to the newest message first. The model server is also started with its cache checkpoints 512 tokens apart instead of the default 8,192: the turn after a tool use read about 1,330 tokens (0.44 s) instead of about 2,600 (0.78 s), and ordinary turns about 50 ms less, in two live runs against three.

Next What is left in the per-turn block changes every turn: the feeling itself, memories, the remaining history excerpts and turn-specific rules. Further gains need a faster card or a smaller model, not more rearranging.

01 / REVIA PROGRESS

Earlier merged changes, plainly.

Six merged fixes are retained through PR #45. Each record keeps the source change separate from what still needs checking.

MergedPR #45

Treat an explicit handover as another person.

“Noor left. My name is Sam” and “I’m a different person. Call me Sam.” are now a privacy boundary with the right explanation, even though they say “my name is” or “call me”.

Detail & evidence scope

After PR44 those turns already withheld the unnamed speaker’s lines, but because they also name the speaker, she was told the lines came before the person gave a name, as if it might be the same person. The speaker’s own words (quotes excluded) are now read for a departure (“Noor left”, “she’s gone now”, “had to go”) or a different speaker (“a different person”, “someone else”, “not the same person”, “my turn”), and such a turn is told someone else spoke before. Full-session regressions start with an unnamed speaker’s private lines and check the real chat requests: the lines never reach the newcomer, the note gives the right reason, and the session records it. “ok she’s gone now…” failed on the first run and shaped the fix; two phrasings written afterwards passed unchanged. The detection is phrase-based and will miss some wordings; a miss only changes the note, because the lines are withheld either way.

Next Watch for missed handover phrasings in live trials.

MergedPR #44

Track who said what, land corrections, keep hand-offs honest.

Withheld lines are now explained instead of guessed at, “she’s four, not three” is saved for the right person, false claims about the past are mostly declined, and “use your agents” is read from the person’s own words.

Detail & evidence scope

Each fix came from a real prompt captured in a live run with the SHA-pinned Qwen3.5-4B through ReviaSession at 32K context, and was measured by replaying that request, including held-out cases written after the fix; samples are small. Identity: words cannot tell someone naming themselves from a new person introducing themselves, so unnamed lines stay withheld (the owner’s choice, keeping the existing privacy rule), and she is told why: asked about what came before, 12/12 replays gave that reason with the note, 0/12 without. A first version that kept those lines leaked Noor’s garden to Sam in a held-out live run and broke a privacy test in CI; both were fixed before merge. Corrections: the memory selector now sees the same person’s previous exchange as context only, so the dog’s corrected age is saved under the speaker 4/4 (0/4 before) and three held-out corrections 12/12. Premises: a note that her past is only this chat and her memories cut false-premise agreement from 7/9 to 1/9, with true premises still 6/6. Delegation: quoted words and “answer directly” inside a question no longer cancel “use your agents”; a hand-off that started nothing is carried to the next turn (invented progress 6/6 → 0/6); the token ceiling now fits reading real files. Acceptance checks are unchanged and nothing retries automatically. Live delegated tasks: 1 of 9 runs produced an accepted report (0 of 6 before).

Next Decide how a correction should reach the revision path after a restart; repeat delegated runs on more tasks.

MergedPR #43

Report what unverified workers found, labelled unconfirmed.

A delegated task that ends unverified now tells you what the workers read and found, instead of “nothing established” or an invented bug.

Detail & evidence scope

A worker that calls its own work unverified ends the run, and its deliverable used to be discarded. Revia’s report then got only a stage list: replaying the live report turn, 6 of 8 replies said “nothing established” and 2 invented bugs nobody had found. The workflow now keeps that deliverable beside the attempt, never as an accepted or reviewed result, and only when it meets the node’s deliverable contract; a review found the first version checked only the hash, and a valid hash over missing or broken sections is now dropped (regression failed before, passes after). The report relays it as the worker’s own unconfirmed claims, with the host receipts as the only facts: 8 of 8 replays relayed what the workers found, and none invented a finding. Verification, review and acceptance are unchanged.

Next Repeat the live delegated runs on more tasks; decide whether an unverified worker should get one bounded retry.

MergedPR #41

Keep the right person, file their plans, reach the agents.

“I meant Mari, not Jo” and “hey, it’s Mari” now find the right person, her own trip is recalled after a restart, and “use your agents” reaches them.

Detail & evidence scope

Found in live multi-turn conversations with the SHA-pinned Qwen3.5-4B through the production session, at the shipped 32K context. A name correction left later facts filed under the rejected name. A returning person was never recognised after a restart. The memory selector filed a speaker’s own plans and pets as unattributed, so a private chat never recalled them (0/6 → 6/6 in replays of the captured request). A request for the agents reached them in 2/10 replays (10/10 after). With no agent reachable, she described a review nobody ran. Workers stopped before opening a file (5/10 → 1/10) or after one of two files (the second was then read 10/10). Each fix has a regression that failed before it. After a restart, live recall now returns the name, tea, instrument and March trip. The installed app is unchanged.

Next Rebuild and requalify the installed app; repeat the live trials over more conversations.

MergedPR #39

Match grounding repairs on whole words.

Harmless words such as “creating” or “relying on” no longer cost a check-in or name reply its sentence.

Detail & evidence scope

PR37’s phrase lists matched parts of words (“eating” inside “creating”, “come over” inside “become overly”, “my bad” inside “my badge”), so harmless sentences in check-ins and first-time name statements could be dropped. The lists now match whole words and phrases. Regressions cover every reported example and confirm that real bodily and mix-up claims are still removed. The installed app is unchanged.

Next Rebuild and requalify the installed app; widen the fixed-prompt check to more history-shaped turns.

MergedPR #37

Keep casual check-ins and stated names grounded.

“What are you up to?” no longer invents a body or offscreen life, and “my name is X, not Y” no longer invents a mix-up nobody had.

Detail & evidence scope

Merged change to conversationStylePolicy.cpp, with conversationGuidanceTests.cpp regressions built from actual replies. Turn guidance plus sentence-level repair; streaming is kept because a repair never withdraws an already released sentence. Measured through the conversation runtime with the SHA-pinned Qwen3.5-4B on three fixed prompts, four passes each: 5/12 before, 12/12 after on CPU, 11/12 on the RTX 5070, where the miss was reply length. Repair still does much of the work, the gates match phrases, and the installed app is unchanged. A post-merge review found the phrase lists matched parts of words (“eating” inside “creating”, “lying on” inside “relying on”), which could drop harmless sentences from these two turn types; PR #39 fixed this with whole-word matching.

Next Covered by PR #39; then rebuild and requalify the installed app.

Still open: the old row stays active until the owner reviews a revision, and a revision is proposed only for narrow first-person phrasings, so after a restart “owns a blue Civic” and “owns a green Civic” were recalled as two cars (the dog case recalled “four” 3/3). Asking the selector to name the replaced value helped 2/12 and hurt a control, so it was not adopted. A 0.35 similarity floor with the nomic embeddings lets unrelated memories in; one run answered “Lisbon … your cousin Jo”. Restart and exit also pause for 40–70 s after “Shutdown complete”; that delay predates PR41 and has not been investigated.

Next Widen tests for premature save claims, quoted/context-only inputs and rapid chat. A narrow candidate guard is verified, not general semantic grounding. The retained PR44 replay evidence does not qualify the current candidate.

One sequence breaker for the repetition sampler instead of four to six, to cut its start-up (about 20 ms per breaker).

Revia · 2026-11-13

Keeping the unchanged settings text in the system message so the model server caches it.

Normal turns read about 60 ms less, but greetings, which are sent without that text, re-read the whole prompt: 2,227 tokens against 745. The server resumes only at the start of a message, so any difference in the system message loses everything. The text rides on the first chat message instead.
