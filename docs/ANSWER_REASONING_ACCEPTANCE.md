## Delivered behavior and ownership

- `Evaluation/calculationVerifier` computes bounded finite arithmetic and supported
  scalar/time/length/mass conversions. It executes no generated code. The existing
  Calculation investigation check and conversation grounding share this owner.
- Normal private replies and `EvaluateTurn` receive the same current-turn grounding.
  Literal arithmetic can avoid model interpretation; word problems use bounded
  proposals linked to exact supplied source spans. A successful result verifies the
  proposed operation, not whether the model chose the right premises or expression.
- Investigation verification keeps its existing canonical foreground contract,
  authority, scope and durable journal admission. Ordinary conversation observations
  remain ephemeral. Cancellation and admission revocation are checked around work.
- Explicit missing-premise cues can withhold calculation and add a conditional
  clarification note instructing the generator not to substitute zero for missing
  amounts. Independent, symbolic and conditional answers remain allowed. Cue
  coverage is deliberately limited; successful ambiguity answers need not have
  taken this guard route.
- The existing reply contract admits restricted object/array schemas, natural schema
  introductions, compatible JSON delivery reminders and identical closed key
  reaffirmations. Latest replacements and withdrawals remain authoritative.
  Provider grammar and final validation use the same admitted contract. Invalid
  structure cannot be delivered or remembered as a successful response; security
  refusals keep their authority. No expected answer, numeric repair or key coercion
  is added to generation.

The authored personality profile, final-response temperature and ordinary renderer
are unchanged. This is the restricted arithmetic part of COG-12 plus explicit
reply-shape reliability. Broader generated-code verification, source-claim gates
and the full upgrade roadmap are not marked complete.
