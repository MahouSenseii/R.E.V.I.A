# Answer reasoning and shape follow-through

This slice continues the complete upgrade plan's answer-quality work. It implements
the restricted local arithmetic part of COG-12 and stronger explicit reply-shape
contracts. It does not mark the broader COG-12 code-test or source-claim gates
complete. The original plan remains the roadmap; delivered status requires evidence.

## Design

One pure native arithmetic owner accepts bounded numeric expressions and a finite
unit table. It never runs code, resolves names or accesses files. Both conversation
grounding and the existing Calculation investigation check use that owner. A
computed receipt proves the declared operation; a model's translation of a word
problem remains an interpretation. Normal and evaluation turns use the same
grounding helper before the existing final conversation generator.

The existing replyFormat owner carries a turn-local structured contract. Explicit
keys and admitted schema constraints reach provider grammar and final validation.
No expected evaluation values enter the generator. Unsupported or ambiguous
constraints retain generic format handling. Validation does not rename, coerce,
drop or fill fields. Security refusals retain their existing authority.

The authored profile, temperature and ordinary conversational renderer remain the
personality owners. Small talk does not trigger arithmetic deliberation. Mechanical
accuracy and human judgment of personality remain separate measurements.

## Decisions

- Reuse existing owners instead of enabling the entire iterative investigation loop
  for simple arithmetic: its optional gate does not cover ordinary or evaluation turns.
- Do not patch final numbers or JSON keys. The generator receives only actual
  computation receipts and explicit user constraints; independent oracles score output.
- User approval to continue and merge verified work is already present in this task.
- The parser computes finite double-precision arithmetic, not exact decimal or
  arbitrary-precision mathematics. It refuses unsupported units and operations.
- Word-problem receipts verify arithmetic on a model-proposed expression. Exact
  source excerpts establish provenance, not the correctness of that interpretation.
- Investigation receipts retain the existing foreground task contract and scope;
  admission is rechecked around journaling. Conversation observations remain local
  to the current turn and do not create an alternate persistent evidence store.
- Shared-file ownership: shape worker owns replyFormat, provider and conversationAgent;
  Director owns conversationRuntime, investigation adapters and CMake registration;
  arithmetic worker owns only its new evaluator header, implementation and tests.

## Initial live assessment and activation correction

The first frozen 20-case/three-seed campaign scored 37/60 versus the retained
baseline's 39/60. All 33 interpretation requests returned empty calculation
arrays, and none of the 60 final requests contained native observations. Those
receipts remain unchanged and do not support an arithmetic accuracy benefit.
The first cohort is now development evidence after this diagnosis.

The correction distinguishes JSON transport from quoted conversation, pins short
source choices to actual supplied text, and extracts literal expressions only when
the complete remainder is admitted presentation guidance. Corrections and extra
tasks still defer. Long current sources retain excerpt handling; raw format clauses
are bounded and intent whitespace is compacted without changing source bytes.
A separate independent 12-case/36-slot cohort was frozen before corrected
candidate outcomes. Final results belong in the delivery acceptance report.
