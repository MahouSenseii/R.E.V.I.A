# Genuine Art Integration Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement these tasks in order. The Director coordinates the shared build and final independent review. Do not stage or commit.

**Goal:** Natural picture requests produce verified raster artifacts through a cancellable local image worker while diagrams retain their existing renderer.

**Architecture:** Visual owns classification, provider transport, job state and worker lifetime. DocumentWorkshop coordinates artifact publication, and ReviaSession retains admission and event dispatch. Reuse the existing resource plan and monitor; load lazily and release image weights after each job by default.

**Tech Stack:** C++20, Windows process jobs and image decoding, authenticated loopback HTTP, Python Diffusers/Pillow.

**Spec:** `docs/CAPABILITY_UPGRADE_DESIGN.md`, package 3.

## Global Constraints

- Preserve companion, audience and cancellation admission before effects and publication.
- Add no second scheduler, general executable workflow, model download, or image daemon.
- Keep provider failures distinct from successful file integrity and from subjective art quality.
- SD-Turbo uses 512px, 1–4 steps and guidance 0. Configurable conventional Diffusers models retain their explicit parameters.
- The Director owns ReviaSession, CMake and configuration parsing/defaults. Shared-build commands require coordination.

## Review Focus

- Conversation about a drawing and negated drawing requests must not create files (task 1).
- Stop during model load or denoising must finish promptly without publishing output (tasks 2–3).
- Worker-returned foreign, stale, corrupt or wrong-size files must not become artifacts (tasks 2–3).
- GPU contention and explicit unavailable devices must report actual placement/failure (task 2).
- Retired companion/audience results must not publish; restart and unload preserve honest state (task 3).

## Evidence and decisions

- Initial inspection: image runtime and weights were absent. The Director subsequently authorized and installed the primary ImageGen runtime/SD-Turbo weights and authorized the measured SDXL-Turbo fp16 comparison.
- The existing worker is a synchronous HTTP call holding generation ownership; Stop cannot interrupt its native transport. Native completion currently trusts a returned path without decoding or digest verification.
- RED: initial Python 14 tests had eight expected failures; native natural policy failed a generate-illustration request; native artifact verifier was absent. GREEN: current Python provider suite has 16 passing tests on the installed venv, including real Pillow decoding. Standalone routing, native artifact verification and native cancellation/restart/admission checks pass.
- Additional RED→GREEN regressions: stale loaded status after release; missing fp16 variant; native malformed completion retaining succeeded=true; chartreuse word-boundary routing; negation of a drawing detail; SDXL working set consuming shared reserve.
- Actual native SD-Turbo and SDXL-Turbo generation, active cancellation, restart and unload succeeded. Timings, GPU peaks, artifact paths and visual limitations are recorded in `docs/IMAGE_GENERATION.md` and local `build/art-acceptance*/acceptance.json`.
- Ruling: character consistency across scenes and reference editing remain unqualified. Exact repeated seeds are not evidence of character identity, and the checked art samples each miss some prompt constraints.
