# Verified process and operator implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute bounded, explicitly admitted native processes and retain independent acceptance and recovery in the existing operator loop.

**Architecture:** Process owns child lifetime, redirected output and job cleanup. Actions and Policy admit typed requests; Goals owns bounded iteration and acceptance while runtime adapters supply observations and verification. Existing browser research remains unchanged.

**Tech Stack:** C++20, Windows CreateProcess/Job Objects, nlohmann JSON, existing native fixture checks.

**Spec:** `docs/CAPABILITY_UPGRADE_DESIGN.md`, package 2.

## Global constraints

- Public contracts and private implementations mirror the owning domain.
- No shell command string: executable and argument vector are distinct; command interpreters require a separate explicit grant.
- Disabled capabilities, revoked admission, cancellation and unavailable native support fail closed.
- Root owns CMake, config persistence, session wiring and documentation integration. No staging or commits by this worker.
- Production edits start only after the shared baseline is recorded; root serializes build commands.

## Review focus

- Quoted/empty/Unicode arguments must survive native quoting without shell interpretation.
- A timed out or cancelled parent cannot leave children alive or inherited output handles blocking collection.
- Nonzero exit and truncated output retain their real status and bounded output.
- A provider completion claim cannot turn an unaccepted or empty task into success.
- Repeated wait/reobserve/vision decisions consume budgets and remain cancellable.
