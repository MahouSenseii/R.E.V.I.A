# Public text demo implementation plan

> Use test-driven development and independent subsystem implementation followed by integration and a fresh security review.

**Goal:** Browser guests receive filtered local Revia replies with isolated ephemeral state and owner controls.
**Architecture:** Static Portfolio -> single bounded relay <- outbound connector -> authenticated loopback guest runtime -> existing local model and final filters.
**Stack:** C++20/cpp-httplib, Node 24 LTS and maintained WebSocket transport, existing plain JS/Webpack frontend.
**Spec:** ../specs/2026-09-22-web-demo-design.md

## Global constraints

Work on main in both existing repositories. Preserve unrelated changes. Text only. No credentials in files. Public defaults disabled. No guest desktop, file, shell, camera, internet, private memory or relationship authority. No transcript disk IPC. No remote deployment claim without evidence.

## Review focus

1. An owner request arriving while guest inference is waiting/running must cancel only the guest and not wait on its lifecycle lock.
2. Cancellation followed immediately by new submission must not overlap native work or append stale history.
3. Deleted/expired sessions, stale epochs and old tokens must never resume context.
4. Lost submission responses must retry the same idempotency key/body without executing twice.
5. Route cleanup during session creation/polling must abort timers and destroy a late-created session.
