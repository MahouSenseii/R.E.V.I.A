# Games, Computer Use, Browsing and Sandboxing for Revia (state as of late Sept 2026)

Scope: how AI agents (and AI VTubers) play games, operate desktops, and browse the web; how to sandbox them on a Windows 11 host (RTX 5070 12 GB + RTX 2070 Super 8 GB), including moving Revia's "acting environment" into a VM and putting that VM on stream. Revia already has a guarded UI Automation desktop executor, a visible locked-down lookup browser, and approval policies (see `docs/ARCHITECTURE.md` in this repo: `UiaElementLocator`, `CapabilityPolicy`, `DesktopActionRateLimiter`, `InternetSearchExecutor`; "the model supplies a plain query, never a URL, selector, script, or browser command"). These notes focus on what improves on that.

Reliability legend: **[2026]** = dated 2026 source; **[older]** = 2023–2025 work that is still relevant but may be superseded; **[self-reported]** = vendor claim not independently verified; **[secondary]** = blog/aggregator rather than primary source.

## 1. How do AI agents (and AI VTubers) play games, and which approach is feasible for which genre?

### Takeaway
Nothing that works well in 2026 plays games through "LLM looks at pixels and presses keys". AI VTubers and research systems use one of three patterns: (a) a **dedicated specialist bot** (neural net / RL / scripted pathfinding) for real-time play, with the LLM only chatting or setting goals; (b) a **structured game API/mod** that exposes game state and legal actions to the LLM as JSON (Neuro-sama's official SDK, Mineflayer for Minecraft); or (c) a **heavily engineered pixel harness** that is slow, turn-based-only in practice, and takes days to months (Claude/Gemini Plays Pokémon). Generalist pixel agents (SIMA 2, Lumine, UI-TARS-2) are research systems, not something a local companion can run. For Revia: LLM-direct control is feasible for turn-based, card, deck-builder, visual-novel and API-backed sandbox games (Minecraft via Mineflayer); rhythm, FPS, fighting and fast action games need specialized bots, and competitive anti-cheat titles should be off-limits entirely.

**Latency and genre feasibility evidence**
- **VideoGameBench** (2025): 10 1990s games, raw pixels, real time. - **BalatroBench** (Feb 2026): gemini-3-pro-preview cleared the final (24th) round 9 of 15 runs; mistral-large-2512 mostly lost round 1 — [GIGAZINE](https://gigazine.net/gsc_news/en/20260213-balatrobench/) **[2026, secondary]**
- Slay the Spire study (FDG 2024): LLM agents aren't optimal move-finders but show good long-term planning without specialized training — [ACM DL](https://dl.acm.org/doi/10.1145/3649921.3650013) **[older]**

**Anti-cheat and ToS**
- Every major competitive game in 2026 uses one of four kernel-level anti-cheats (EAC, BattlEye, Riot Vanguard, Activision RICOCHET), all issuing hardware bans and doing behavioral analysis — [tech-insider.org](https://tech-insider.org/eac-vs-battleye-vs-vanguard-2026/) **[secondary]**
- BattlEye detects VMs with an `rdtsc;cpuid;rdtsc` timing attack; EAC performs a `vmread` at driver init — [secret.club](https://secret.club/2020/04/13/how-anti-cheats-detect-system-emulation.html) **[older, technique-level]**
- Vanguard On-Demand (June 24, 2026) loads only while the game runs but requires Windows 11 25H2+, Secure Boot, TPM 2.0, IOMMU, VBS and HVCI — [Wikipedia: Riot Vanguard](https://en.wikipedia.org/wiki/Riot_Vanguard) **[2026]**
- Games such as Elden Ring: Nightreign and Arc Raiders refuse to start in a Windows 11 VM ("Cannot run under virtual machine") even with CPU/GPU passthrough — [XDA](https://www.xda-developers.com/i-run-windows-11-as-a-vm-with-gpu-passthrough-for-gaming/)
- `SendInput` events carry the `LLMHF_INJECTED` flag visible to low-level hooks; only a driver can strip it, and kernel anti-cheat can read it before hooks — [GuidedHacking](https://guidedhacking.com/threads/how-to-bypass-sendinput-detection.16318/) **[secondary, cheat-dev forum]**. The ViGEmBus virtual gamepad driver is legitimate/open source but has been reported to publishers as "input spoofing" — [EA Forums](https://forums.ea.com/idea/apex-legends-bug-reports-en/input-spoofing-via-virtual-gamepad-driver-vigembus/13176788)
- Hypixel: bots for games like Bedwars are bannable; admins have said bots aren't inherently banned but non-vanilla packet behavior triggers Watchdog; bans aren't reversed — [Hypixel forums](https://hypixel.net/threads/mineflayer-allowed.3547208/); [minecraftiplist](https://www.minecraftiplist.com/blog/is-mineflayer-allowed-on-hypixel-a-deep-dive-into-minecraft-botting/) **[secondary]**

### Inferences
- **Genre map for Revia** (synthesized from the above):
  - *LLM-direct, feasible now:* turn-based card/deck-builders (Slay the Spire, Balatro, Inscryption, Buckshot Roulette, Liar's Bar), visual novels and text-heavy pausable games, turn-based RPGs **if** a state/action adapter exists. Pixel-only play of these works but is slow (seconds per move); fine for stream pacing where "thinking out loud" is content.
  - *LLM as planner + protocol bot as executor:* Minecraft (Mineflayer/Mindcraft on a **private, offline/LAN server** you own; skill-library pattern from Voyager). The LLM picks goals; Mineflayer's pathfinding/collection plugins do the ticks.
  - *Specialist bot + LLM commentary/coach:* rhythm (osu!), FPS, fighting, racing, platformers — millisecond reaction times rule out VLM loops; Neuro's own osu! bot is a separate network. Chess: use an engine for moves and the LLM for personality (no source gathered on LLM chess strength; standard practice).
  - *Research-only for now:* 3D open-world action via pixels (Lumine, SIMA 2, UI-TARS-2) — not locally runnable or not released for general use.
  - *Off-limits:* anything with kernel anti-cheat or online competitive ToS (bans are hardware-level; VMs are often refused outright).
- **Adopt a Neuro-API-compatible adapter protocol** (websocket, JSON-schema actions, context messages, action force, disposable actions). This gives Revia a typed "game action" surface that fits her existing approval/policy layer much better than raw input, and community games/mods written for Neuro's SDK could plug in. Keep the race-condition guidance.
- A good per-game ladder: official API/mod > memory/state reader or emulator RAM map (Pokémon-style harness) > accessibility/UI tree > pixels. Pixels are the fallback, not the default.
- Stream-safe design: LLM decisions at 0.2–1 Hz with the game paused or turn-based; a reflex layer (scripted/RL) for anything faster than ~1 s.

- Neuro-sama's Minecraft internals (Mineflayer-based or custom?) are not publicly documented; I found no primary source.

## 2. Computer-use agents: state of the art, grounding approaches, and local models in 2026

### Takeaway
Frontier computer-use has passed the OSWorld human baseline (72.4%). Top **self-reported** OSWorld-Verified scores are ~85–86% (Qwen3.8-Max, Claude Mythos/Fable 5, Opus 4.8), and open-weight models now reach the high 70s to low 80s (Qwen3.8-27B 84.3%, Holo3-35B-A3B 82.6%, UI-Mate-27B 77%). On Windows, the best systems **combine the UI Automation tree with vision grounding** (UFO2), which suits Revia's UIA-first executor. A pixel fallback that fits Revia's 12 GB card is realistic in 2026 (UI-Mate-9B, UI-TARS-1.5-7B; Holo3-35B-A3B with CPU offload). The bigger 27–35B models need both GPUs or offloading.

### Inferences
- Revia's UIA-first executor is already the right *primary* grounding on Windows (deterministic, cheap, auditable). What's missing is a **vision fallback** for UIA-blind surfaces (games, Electron/canvas apps, custom-drawn UIs), plus a verify step (screenshot/zoom after each mutable action). UFO2's measured gain from hybrid grounding supports this.
- VRAM estimates (my arithmetic, not sourced): UI-Mate-9B at Q4 is about 5–6 GB, at Q8 about 9–10 GB; UI-TARS-1.5-7B at Q4 is about 4–5 GB; Qwen3.8-27B dense at Q4_K_M is about 16–17 GB of weights, so it won't fit the 12 GB 5070 alone and would need a 5070+2070S split (little room left for KV/vision encoder) or offload. Holo3-35B-A3B (3B active) is the best quality per VRAM with expert offload to system RAM. Practical pick: **UI-Mate-9B or UI-TARS-1.5-7B on the 5070 next to (or time-shared with) Revia's main LLM**, with an opt-in cloud CU API (Claude/GPT-5.4) for hard tasks when the owner allows it.
- Benchmarks are self-reported and run in clean Linux VMs; expect materially lower success on a streamer's real Windows desktop. Keep human approval for consequential actions regardless of scores.
- OmniParser V2 (no LLM, fast) is a cheap way to turn screenshots into clickable element lists that Revia's existing policy layer can reason about ("element #12: 'Buy' button") rather than raw coordinates.

## 3. Browser agents, search APIs, and prompt-injection risk

### Takeaway
For *lookups*, structured search APIs (Brave, Tavily, self-hosted SearXNG) plus a sanitized page fetch are safer and cheaper than a driven browser. For *doing things* on sites, accessibility-snapshot browser control (Playwright MCP) or browser-use/Stagehand is the 2026 norm. OpenAI and Anthropic both say prompt injection is not solved: the best-defended agents still reach ~0.5–1% attack success under benchmark conditions, and much higher with repeated attempts. The strongest mitigations are architectural (plan-then-execute, dual-LLM/quarantine, no credentials, logged-out browsing, domain allowlists, human confirmation), which matches Revia's current "query, never URL" design.

### Cited Findings
- **browser-use**: ~114–117k GitHub stars, MIT, Python; Browser Use CLI 3.0 launched in 2026 ("Browser Harness") — [star-history](https://www.star-history.com/browser-use/browser-use/); [releases](https://github.com/browser-use/browser-use/releases) **[2026]**
- **Playwright MCP** uses **accessibility snapshots** instead of screenshots: each interaction returns a structured tree of accessible elements with stable refs; no vision model required; `browser_take_screenshot` exists as a vision fallback — [Playwright MCP docs: Snapshots](https://playwright.dev/mcp/snapshots); [Playwright MCP intro](https://playwright.dev/mcp/introduction). Reported size ~200–400 tokens per snapshot vs thousands for screenshots — [dev.to](https://dev.to/pointchecknote/browser-automation-with-claude-playwright-mcp-why-accessibility-snapshots-beat-screenshots-2pke) **[secondary]**
- **Stagehand v3**: app code specifies steps ("open reports, inspect the filter…") with the LLM interpreting the page at chosen steps; `agent()` can plan more of the sequence; contrast with Playwright MCP, where the client model does all planning — [fp8.co comparison](https://fp8.co/articles/Browser-Use-vs-Stagehand-vs-Playwright-MCP-AI-Agent-Browser-Automation); [qtrl.ai](https://qtrl.ai/blog/mcp-cli-tools-ai-test-automation) **[secondary]**
- **Search APIs (2026)**: Tavily free tier 1,000 credits/month; Bootstrap $100/month for 15k credits; pay-as-you-go $0.008/credit; results formatted for LLMs. Brave's old free tier (100 queries/day) is closed to new customers and scheduled to end Jan 1, 2027; Brave has its own index of 35B+ pages. SearXNG is self-hosted metasearch with no per-query cost but needs maintenance — [Firecrawl: Brave alternatives](https://www.firecrawl.dev/blog/brave-search-api-alternatives); [Brave: best search APIs 2026](https://brave.com/learn/best-search-api-2026/); [codenote Tavily comparison](https://codenote.net/en/posts/tavily-alternatives-cost-comparison-search-extract-api/) **[secondary; verify prices on vendor pages]**
- **Anthropic (Nov 24, 2025)**: Claude Opus 4.5 reached ~1% attack success in browser use — "A 1% attack success rate—while a significant improvement—still represents meaningful risk." Three layers: RL training for injection resistance; classifiers that "scan all untrusted content that enters the model's context window" (text, manipulated images, deceptive UI); human red teaming — [Anthropic: Mitigating the risk of prompt injections in browser use](https://www.anthropic.com/news/prompt-injection-defenses)
- 2026 reporting: Opus 4.8 browser agent was hijacked 31.5% of the time **without** safeguards, 0.5% with; Opus 5 + Auto Mode defenses 0% across 129 browser scenarios (3.7% model alone); Opus 4.5 in coding: 4.7% at 1 attempt, 33.6% at 10, 63.0% at 100 — [VentureBeat](https://venturebeat.com/security/anthropic-browser-agent-hijacked-31-percent-before-safeguards-engaged) **[2026, secondary summary of Anthropic system-card data]**
- **OpenAI**: prompt injection is "unlikely to ever be fully solved", compared to scams/social engineering. ChatGPT Atlas mitigations: **logged-out mode** (agent works without site sessions) and **watch mode** (user must confirm sensitive actions such as sending messages or payments); advice: give explicit narrow instructions, not "review my emails and take whatever action is needed" — [OpenAI: Understanding prompt injections](https://openai.com/index/prompt-injections/); [OpenAI: Hardening Atlas](https://openai.com/index/hardening-atlas-against-prompt-injection/); [Fortune](https://fortune.com/2025/12/23/openai-ai-browser-prompt-injections-cybersecurity-hackers/)
- **Design patterns** (Google, Microsoft, IBM, ETH Zurich, EPFL et al., Jun 2025): six patterns incl. **Plan-Then-Execute** (commit to tool calls before reading untrusted data), **Dual LLM** (privileged planner never sees untrusted text; quarantined LLM reads it, has no tools, returns typed values), **Code-Then-Execute** (CaMeL). Core principle: once untrusted input is ingested, it must not be able to trigger consequential actions — [arXiv 2506.08837](https://arxiv.org/pdf/2506.08837); [Simon Willison summary](https://simonwillison.net/2025/Jun/13/prompt-injection-design-patterns/); CaMeL: [arXiv 2503.18813](https://www.alphaxiv.org/abs/2503.18813)
- Visual prompt injection against computer-use agents (injected text/images in screenshots) is its own benchmarked attack class — [VPI-Bench, arXiv 2506.02456](https://arxiv.org/pdf/2506.02456); hybrid web+OS adversarial testing — [RedTeamCUA, arXiv 2505.21936](https://arxiv.org/pdf/2505.21936)

### Inferences
- Keep Revia's current lookup path (bounded query → fixed API sources / visible read-only browser) as the default. It's effectively plan-then-execute. Add **SearXNG in a container/VM** as a local-first option, with Brave/Tavily as opt-in paid fallbacks. Since Brave's free tier is going away, don't design around it.
- For *acting* on the web (logged-in tasks), run the browser **inside the acting VM**, logged out by default, and use a **quarantined reader**: page content goes to a no-tools summarizer, and Revia's planner sees only typed extractions. Any action derived after reading untrusted content needs approval. Screenshots from games/streams/chat overlays count as untrusted content too (visual injection), and so does Twitch chat.
- Prefer accessibility-snapshot control (Playwright MCP-style refs) over pixels for browsers. It's cheaper, deterministic, and fits Revia's typed-element model; use pixels/zoom only for canvas content.

### Gaps
- SearXNG's reliability (upstream engines rate-limiting or CAPTCHA-ing self-hosted instances) was not researched.
- Stagehand and Playwright MCP star counts/licenses not fetched; Browserbase-style hosted browser pricing not researched (not local-first anyway).
- No independent 2026 benchmark comparing injection rates of *local* open-weight models; likely much weaker than frontier models (unverified), which argues for architectural defenses.

## 4. Sandboxing and VMs on Windows 11: options, streaming the VM, input, GPU, anti-cheat, security

### Takeaway
On a Windows 11 Pro host the realistic acting environment is a **Hyper-V Windows 11 guest with GPU paravirtualization (GPU-PV)**. It's officially unsupported on client Windows but widely used (Easy-GPU-PV, now archived and replaced by its author's "App Sandbox" project). It gives DirectX games acceptable performance but no Vulkan and flaky OpenGL, needs a dummy/virtual display, and breaks Enhanced Session. Stream it by running **Sunshine/Apollo or Parsec inside the VM** and window-capturing the client on the host in OBS. Use **Hyper-V sockets** for the host↔VM control channel (no network needed). Windows Sandbox is good for disposable browsing/file-opening but is single-instance and non-persistent. Windows 11 "Agent Workspace" is a lighter, non-VM agent session in private preview. Games with kernel anti-cheat will often refuse to run in a VM and may flag synthetic input, so a VM stage is for single-player, offline, modded or API-backed games.

### Cited Findings

**Hyper-V GPU partitioning / paravirtualization**
- Official **GPU-P** (SR-IOV hardware partitioning) is documented for **Windows Server 2025** hosts with specific data-center GPUs (NVIDIA A2/A10/A16/A40/L2/L4/L40/L40S, RTX Pro 6000 Blackwell Server Edition, AMD Radeon PRO V710); guests: Windows 10+, Server 2019+, Ubuntu 18.04–22.04 — [Microsoft Learn: GPU partitioning](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/gpu-partitioning) (updated May 2026)
- Microsoft troubleshooting: "DDA and GPU-P aren't supported on desktop-class hardware or client operating systems such as Windows 10 or 11 Pro" — [Microsoft Learn troubleshooting](https://learn.microsoft.com/en-us/troubleshoot/windows-server/virtualization/troubleshoot-hyper-v-gpu-assignment-partitioning-passthrough-issues)
- **Easy-GPU-PV** (the unofficial client route): host Windows 10 20H1+/Windows 11 Pro/Enterprise/Education; NVIDIA/AMD desktop GPUs or Intel iGPU; GPU must support hardware encode (NVENC/QuickSync/AMF); host and VM Windows versions should match; **multi-GPU selection only on Windows 11**; "Always use a GPU accelerated remote desktop / game streaming app"; "A powered on display / HDMI dummy dongle must be plugged into the GPU"; **Hyper-V Enhanced Session causes "broken behaviour and black screens"**; **"Vulkan renderer is unavailable and GL games may or may not work"**; GPU driver updates require re-copying drivers into the VM. **Repository archived June 1, 2026, replaced by "App Sandbox"** — [GitHub jamesstringer90/Easy-GPU-PV](https://github.com/jamesstringer90/Easy-GPU-PV) **[2026]**
- GPU-PV on client Windows is the same WDDM GPU virtualization tech used by WSL2 and Windows Sandbox; the author's newer "App Sandbox" sets up a VM from a Windows 11 or Ubuntu 26.04 ISO with GPU support on both — [Easy-GPU-PV README](https://github.com/jamesstringer90/Easy-GPU-PV/blob/main/README.md) (search-result summary; App Sandbox repo itself not read)
- Anti-cheat in a Hyper-V VM has kernel access *inside* the VM but not to the host — [ByteBreach: anti-cheat dev env in Hyper-V](https://bytebreach.com/posts/hyperv-ac-setup/) **[secondary]**

**Windows Sandbox**
- Disposable, hypervisor-isolated Windows desktop; fresh each launch; closing deletes all state; since 22H2 data persists through restarts initiated *inside* the sandbox; supports vGPU; **networking on by default** ("can expose untrusted applications to the internal network"; disable via .wsb); Pro/Enterprise/Education only, **not Home**; **only one instance at a time** — [Microsoft Learn: Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-overview) (Mar 2026)
- Windows 11 24H2+ adds the **`wsb` CLI**, including `wsb exec --id <id> -c app.exe -r System` to run commands inside a running sandbox and return the exit code — [Microsoft Learn: Windows Sandbox CLI](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-cli); `wsb.exe` is also listed on LOLBAS (usable for defense evasion) — [LOLBAS](https://lolbas-project.github.io/lolbas/OtherMSBinaries/Wsb/)
- vGPU in the sandbox increases attack surface; hardened configs disable networking and vGPU, disable clipboard, and map one host folder read-only; on 24H2 some inbox apps (Notepad, Calculator) aren't available inside — [KomuraSoft .wsb guide](https://comcomponent.com/en/blog/2026/04/13/000-windows-sandbox-appdev-validation-guide/) **[2026, secondary]**; [Microsoft Learn: .wsb configuration](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file); [sample configs](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-sample-configuration)

**Windows 11 Agent Workspace (new, preview)**
- "A separate, contained space in Windows where you can grant agents access to your apps and files so they can complete tasks for you in the background"; each agent gets **its own low-privilege Windows account** and session; access to the known folders (Documents, Downloads, Desktop, Music, Pictures, Videos) with per-agent "Allow Always / Ask every time / Never allow" (build 26100.7344+); principles: non-repudiation ("All actions of an agent are observable and distinguishable from those taken by a user"), confidentiality, authorization; **not a full VM** ("more efficient than a full virtual machine such as Windows Sandbox"); private preview for Insiders, admin toggle at Settings → System → AI Components → Experimental agentic features — [Microsoft Support: Experimental agentic features](https://support.microsoft.com/en-us/windows/experimental-agentic-features-a25ede8a-e4c2-4841-85a8-44839191dfb3) **[2026, preview]**

**Host ↔ VM control channel**
- **Hyper-V sockets (AF_HYPERV / hvsocket)**: host Windows 10+ / guest Windows 10+ (and Linux via AF_VSOCK); "All communication over Hyper-V sockets runs without using networking and all data stays on the same physical memory"; addressed by VM ID GUID + service GUID registered under `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Virtualization\GuestCommunicationServices`; stream only; "No block memory (not the best for backup/video)"; `HV_GUID_PARENT` lets the guest connect to its host — [Microsoft Learn: Make your own integration services](https://learn.microsoft.com/en-us/virtualization/hyper-v-on-windows/user-guide/make-integration-service)

**Getting the VM onto the stream**
- OBS on the host: add a **Window Capture** of the VM viewer window; OBS itself isn't designed to run inside a VM (poor graphics/audio device support) — [OBS forum: capture a VM screen from the host](https://obsproject.com/forum/threads/capture-a-vm-screen-from-the-host.54700/) **[community]**
- Easy-GPU-PV's intended viewer is **Parsec** (low-latency, GPU-encoded) — [Easy-GPU-PV](https://github.com/jamesstringer90/Easy-GPU-PV). **Parsec Virtual Display Driver** provides a virtual monitor for headless hosts/VMs so capture keeps working without a physical display — [GitHub nomi-san/parsec-vdd](https://github.com/nomi-san/parsec-vdd); [Parsec cloud workstation guide](https://support.parsec.app/hc/en-us/articles/32381875912468-Cloud-Workstation-Setup-Guide)
- **Sunshine** (host) + **Moonlight** (client) is the self-hosted alternative; the **Apollo** fork creates a per-client **virtual display** (SudoVDA) matched to the client's resolution/refresh/HDR, removed on disconnect, with client permission management and clipboard sync — [Apollo vs Sunshine 2026](https://tech-insider.org/apollo-vs-sunshine-game-streaming-2026/); [GitHub ClassicOldSong/Apollo](https://github.com/ClassicOldSong/Apollo) **[2026, secondary comparison]**
- Reported: in Hyper-V guests the built-in Hyper-V monitor can't be disconnected, which can stop Parsec/Sunshine from falling back to their own virtual display (search-result summary; originating page not confirmed) — [parsec-vdd](https://github.com/nomi-san/parsec-vdd) **[unverified]**

**Other isolation options**
- Anthropic's docs recommend "a dedicated virtual machine or container with minimal privileges" for computer use, and an allowlist of domains — [Claude docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool). Anthropic's reference implementation is a Docker container — [computer-use-demo README](https://github.com/anthropics/anthropic-quickstarts/blob/main/computer-use-demo/README.md)
- Proxmox/KVM with full GPU passthrough on a separate host runs most games well, but some anti-cheat titles still refuse VMs — [XDA](https://www.xda-developers.com/i-run-windows-11-as-a-vm-with-gpu-passthrough-for-gaming/)
- Cua provides SDKs for driving Windows Sandbox and VM/container sandboxes programmatically — [GitHub trycua/cua](https://github.com/trycua/cua)

### Inferences
- **Option ranking for Revia's host** (Win11 Pro, 5070 + 2070S):
  1. **Hyper-V Win11 guest + GPU-PV bound to the RTX 2070 Super** (Easy-GPU-PV's Windows-11-only multi-GPU selection suggests this is possible), leaving the RTX 5070 for Revia's LLM/TTS/avatar on the host. Good for DirectX single-player games, desktop apps and browsers. Not for Vulkan-only games or anti-cheat titles. Whether Blackwell (RTX 50) / Turing (RTX 20) behave under GPU-PV with 2026 drivers is unverified; test first.
  2. **Windows Sandbox** for throwaway, high-risk tasks (opening unknown files, sketchy pages) driven via `wsb exec`/mapped folders. Single instance, no persistent game installs, so it's unsuitable as the main stage.
  3. **Agent Workspace**: watch it. It gives OS-level agent identity and folder consent without VM overhead, but it's private preview and a weaker boundary than a VM.
  4. **Docker/WSL2 container** for a headless browser, SearXNG, and code execution (no GUI games).
  5. **Dedicated second PC**: strongest isolation and real hardware (fewer "VM detected" refusals), at the cost of hardware and capture (HDMI capture card or NDI). Synthetic-input detection still applies.
- **Streaming path:** in-VM Apollo/Sunshine (virtual display, NVENC via GPU-PV) → Moonlight window on host → OBS Window Capture; or Parsec + Parsec VDD. Keep the VM viewer on a dedicated OBS scene so a kill switch can cut to a "Revia is thinking" scene instantly. VMConnect basic-session capture is a no-GPU fallback for desktop-app demos.
- **Agent perception vs stream video are separate paths:** hvsocket is explicitly "not the best for video", so ship downscaled screenshots (e.g., 1280x720 JPEG on demand, which also matches Anthropic's recommended resolutions) over hvsocket to the host model, and let Sunshine/Parsec handle the 60 fps stream.
- **Input injection inside the VM:** SendInput/UIA from an in-VM agent works for normal apps and most single-player games. Games that read raw input may ignore it, and ViGEmBus gamepad emulation is an option for controller-driven games. Treat anything with kernel anti-cheat as out of scope; injected-input flags plus VM detection make bans likely.
- **Security boundaries:** no host credentials or password manager in the VM (separate local account, no Microsoft account sign-in, no host clipboard/drive sharing by default); a dedicated Hyper-V virtual switch (NAT/internal) with a host-side egress allowlist or proxy; checkpoints before each session with revert on anomaly; kill switch = host-side `Stop-VM -TurnOff` / `Save-VM` plus closing the hvsocket listener, independent of anything running in the guest.

### Gaps
- Whether Hyper-V **checkpoints** work on VMs with a GPU-PV adapter attached (needed for snapshot/rollback) was not verified.
- The successor "App Sandbox" project (URL, license, whether it supports Windows 11 client hosts and multi-GPU selection) was not read directly.
- GPU-PV compatibility with RTX 50-series (Blackwell) consumer drivers on Windows 11 25H2 was not verified; 2026 sources claiming consumer GPU-P is "stable" were aggregator-level only.
- QEMU/KVM on a Linux host with Looking Glass (low-latency VM framebuffer sharing) was not researched.
- No measured numbers found for GPU-PV gaming performance overhead vs bare metal.
- Hyper-V Enhanced Session behavior without GPU-PV (fine for desktop-app demos?) and audio routing from VM to stream were not researched.

## 5. Recommended architecture: in-VM action runtime vs host-side control, permissions and approval

### Takeaway
Keep Revia's **brain, memory, policy, approvals and stream presence on the host**. Move her **hands and eyes** (UIA executor, input injection, screenshots, browser, game adapters) into a **VM-resident "action runtime"** that the host drives over an authenticated Hyper-V socket with a typed action protocol. Rank action channels by structure: game API/mod adapters (Neuro-SDK-style) > UIA/accessibility snapshots > pixel grounding with a local GUI model. Put anything real-time behind specialist bots the LLM only commands. This follows vendor guidance (dedicated VM, no credentials, allowlisted network, human confirmation), Windows' own direction (separate agent identity, per-agent consent, non-repudiation), and the plan-then-execute / dual-LLM injection defenses.

### Cited Findings
- Vendor guidance converges on: dedicated VM/container with minimal privileges, no credentials, domain allowlist, human confirmation for consequential or consent-requiring actions, and injection classifiers on tool output — [Claude computer use docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool); per-step safety service + confirmation for high-stakes actions — [Gemini computer use docs](https://ai.google.dev/gemini-api/docs/computer-use); logged-out mode and watch mode — [OpenAI prompt injections](https://openai.com/index/prompt-injections/)
- Windows' agent model: separate agent account/session, per-agent folder consent, "All actions of an agent are observable and distinguishable from those taken by a user", "Users approve all queries for user data as well as actions taken" — [Microsoft Support: Experimental agentic features](https://support.microsoft.com/en-us/windows/experimental-agentic-features-a25ede8a-e4c2-4841-85a8-44839191dfb3)
- UFO2 runs automation in an isolated Picture-in-Picture virtual desktop so agent and user don't collide, with hybrid UIA+vision grounding — [UFO2 paper](https://arxiv.org/abs/2504.14603)
- Plan-then-execute and dual-LLM patterns prevent untrusted content from choosing actions — [arXiv 2506.08837](https://arxiv.org/pdf/2506.08837)
- Hyper-V sockets give a network-free host↔guest channel with registered service GUIDs — [Microsoft Learn: hvsocket](https://learn.microsoft.com/en-us/virtualization/hyper-v-on-windows/user-guide/make-integration-service)
- The Neuro API shows a working typed game-action protocol (register actions with JSON schema, context, force, results) proven on stream — [VedalAI/neuro-sdk](https://github.com/VedalAI/neuro-sdk)
- Mindcraft's LLM code execution is "sandboxed, but still vulnerable to injection attacks" and must not face public servers — [Mindcraft](https://github.com/mindcraft-bots/mindcraft)
- Revia already enforces "the model supplies a plain query, never a URL, selector, script, or browser command", single-owner element resolution (`UiaElementLocator`), capability scopes and rate limits — `docs/ARCHITECTURE.md` (this repo)

### Inferences
- **Proposed layout**
  - *Host (trusted):* Revia LLM (RTX 5070), memory, persona, TTS/avatar, OBS; **Policy & Approval service** (existing `CapabilityPolicy`, rate limiter, approval UI and chat-visible approval prompts); **Action Broker** that turns model intents into typed actions and signs/sequences them; kill switch; audit log (every action with screenshot before/after, tagged "agent" per the non-repudiation principle).
  - *VM "Revia-Stage" (untrusted, disposable):* **Action Runtime** service (port of the existing `DesktopControlExecutor` + `UiaElementLocator` + input injector + screenshot/zoom + optional OmniParser/UI-Mate grounding), visible browser (logged-out profile), game adapters (Neuro-API-compatible websocket server, Mineflayer bot process, emulator-RAM readers), Sunshine/Apollo for the stream. GPU-PV on the RTX 2070 Super.
  - *Channel:* hvsocket with a registered service GUID; host is the only initiator of mutable actions; the runtime returns observations (UIA tree slices, snapshot refs, downscaled screenshots, game state JSON) that the host treats as **untrusted** data. No SMB shares, no clipboard sync by default.
  - *Network:* the VM sits on its own vSwitch; egress goes through a host-side allowlisting proxy (search API domains, game servers you own, update endpoints). SearXNG in a container on that segment.
- **Permission tiers** (extending current approval policies): T0 observe-only (screenshots, UIA reads, game state); T1 reversible in-VM actions inside an approved app/game (auto-approved, rate-limited, logged); T2 outbound communication, installs, purchases, logins, file export to host (always needs owner approval, shown on stream as a prompt); T3 host actions (disabled by default; only through the existing host executor with per-action approval). Any action planned *after* reading untrusted content (web page, chat, OCR of a screen) inherits at least T2 unless it's in a pre-committed plan (plan-then-execute).
- **Game control stack:** (1) adapter/API games: the LLM chooses from registered actions (turn-based, Neuro-SDK style); (2) Minecraft: the LLM issues goals, Mineflayer executes, private server only, `allow_insecure_coding` off; (3) pixel games: local GUI model + pause-based loop (0.2–1 Hz) with game paused between decisions where possible; (4) real-time/rhythm: a specialist bot (scripted/RL) with the LLM as coach/commentator; (5) anti-cheat or online-competitive titles: blocked by policy (an executable denylist in `CapabilityPolicy`).
- **Rollback & kill switch:** checkpoint "clean-stage" before each stream (verify GPU-PV compatibility); a hotkey + chat-mod command on the host triggers: cut the OBS scene, drop the hvsocket, `Save-VM` (preserves state for review) or `Stop-VM -TurnOff`; revert to checkpoint after suspicious sessions.
- **Why in-VM runtime beats host-side control of the VM window:** injecting input from the host into a VMConnect/Parsec window is fragile (focus, scaling, input capture). The UIA tree of guest apps isn't visible from the host at all. An in-guest runtime keeps Revia's existing UIA-first design working unchanged, just behind a VM boundary.
- **Cloud option:** frontier CU APIs (Claude `computer_toolset_20260801`, GPT-5.4 computer tool) can drive the same in-VM runtime as an opt-in "hard task" mode, since their action vocabularies map onto the same screenshot/click/type/zoom primitives. Keep them off by default to respect local-first design.

### Gaps
- No public reference implementation of an AI VTuber with a VM-resident action runtime was found; this architecture is synthesized, not copied.
- Latency budget of hvsocket round-trips plus a local 7–9B GUI model per step on the 5070 while the main LLM also runs was not measured; needs a spike test.
- Whether Windows Agent Workspace will expose APIs third-party apps like Revia can use (vs. only Microsoft Copilot agents) is unclear from the preview docs.
